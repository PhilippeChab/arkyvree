# Frontend

How the client (`client/src/`) is written. Read it before writing or changing client code: every pattern the client follows is here, with the component or hook that is its one way and the lint rule that holds it.

Lint holds what it can, with no exception (`bun run lint`: the `arkyvree/*` rules of `lint/frontend.mjs`, `lint/components.mjs`, `lint/styles.mjs`, `lint/wording.mjs` and `lint/feedback.mjs`, and the repo's general ones in [AGENTS.md](../AGENTS.md)). What lint can't judge is decided here: which empty state a place takes, a framed or a bare table, which dialog wrapper. A look the app doesn't have yet is the owner's call: propose it, never invent one, and never flatten one place's look into another's unasked.

## Before finishing

- TypeScript passes: `bunx tsgo --noEmit -p .`
- `bun run lint` passes (`bun run lint --fix` writes what it can), and `bun run format:check` (`bunx oxfmt` the changed files, never a directory)
- The impacted tests pass: `bun run test:changed`, and `tests/client` for the client's pure modules
- A change users see is looked at: the screens it touches, at a phone's width (375px) and a desktop's, in both themes

## A page

- Named `XPage.tsx` under `pages/` (`XDetailsPage` for a record's), its default export `export default function XPage` (`arkyvree/component-files`); routes import it lazily
- It names the browser tab with `usePageTitle(title)`
- It fades in through `PageTransition` (`EntityDetailLayout`, `InviteLandingPage` and the auth pages' `AuthPage` carry it for theirs)
- It opens on its header, its content 32px below (`arkyvree/page-gaps`): `PageHeader` for a list or an account page, `DetailPageHeader` for a ruleset or a campaign, `CharacterHeader` for a character's sheet, `EntityDetailLayout` for a ruleset entity's page
- It shows `PageLoader` while it first loads (a skeleton of itself where its shape is known: the sheet's `CharacterDetailSkeleton`, `EntityDetailLayout`'s), and `PageError` when it fails

## Mobile First

- Develop mobile first — all new components and layouts must work on small screens (375px) before scaling up
- Use `useIsMobile()` hook (`client/src/hooks/useIsMobile.ts`) for mobile-specific branching
- Use MUI responsive sx props (`{ xs: ..., sm: ..., md: ... }`) over static values
- All `<Dialog>` components must include `fullScreen={isMobile}` (`arkyvree/dialog-conventions`). A full-screen dialog has no backdrop to tap, so every dialog needs its own way out: a Close or Cancel button
- Never use hover-only interactions without a touch-friendly fallback. A table's row actions spread `ROW_ACTIONS_HOVER_SX` into the row's `sx` and `ROW_ACTIONS_SX` into their box (`className="row-actions"`): revealed on hover with a pointer, always shown on touch screens and while focused

## Components

- A component is a `function` that destructures its props in its signature, typed by one named type: its own (`interface CardProps`, `type CardProps = Omit<…>`) or one its family shares (`RulesetSectionProps`), never written in place (`arkyvree/component-props`). React's types and functions are named imports (`import { type ReactNode } from "react"`), never `React.` or a default `React`, and a component takes its `ref` as a prop, never through `forwardRef` (`arkyvree/react-imports`)
- Every control has an accessible name. An icon-only `IconButton` is named by its `aria-label`, whether or not a `Tooltip` shows its name (`arkyvree/accessible-icon-buttons`). A `Tooltip` on an element its own text names (a chip, a list option, a labelled button) takes `describeChild`, otherwise its title replaces the element's name, and one around a control that can be disabled wraps it in a `<span>`, which still takes the pointer (`arkyvree/tooltips`). A switch or checkbox is the `control` of a `FormControlLabel`, and a dialog without a `DialogTitle` points `aria-labelledby` at its heading. A button that flips between two states keeps one label, naming what it turns on (`"Star ruleset"`, `` `${name} details` ``), and says which state it's in: `aria-pressed`, or `aria-expanded` when it shows or hides something, never a label that flips (`Star` / `Unstar`, `Show` / `Hide`; `arkyvree/toggle-states`)
- Everything a click opens is reachable from the keyboard. A row or card that opens or expands on click spreads `clickableProps(onActivate)` and puts `CLICKABLE_SX` in its `sx` (`components/common`): focusable, activated with Enter or Space, with a focus ring; a bare `onClick` on a box, a row or a text is refused (`arkyvree/clickable-elements`). A control inside it (a link, a row action, a chip) keeps its click, and so does a menu or a dialog it opened, whose clicks reach the row through React: `clickableProps` leaves them be, so none stops its event (a control inside MUI's own toggles, an accordion's summary or a tree item, still does). What shows or hides something leads with one arrow, `ExpandArrow`, turned up while open: a heading's toggle is its `ToggleLabel` (`<SubsectionTitle><ToggleLabel open onToggle>Granted (3)</ToggleLabel></SubsectionTitle>`, its `label` naming the arrow alone when the heading holds a link), a table row's is `toggleProps(open, onToggle, "row")` with the arrow in its first cell, and an accordion's is its `expandIcon`, which the theme puts before its title (`arkyvree/expand-arrows`). A control that only navigates is a link (`component={Link} to`; a page's Back, `DetailPageHeader`'s, `EntityDetailLayout`'s and `PageError`'s, takes where it goes, `backTo`), an external one an anchor (`component="a" href target="_blank" rel="noopener noreferrer"`), never `window.open`; React Router's `Link` is imported as `Link`, MUI's as `MuiLink` (`arkyvree/navigation`)
- An icon comes from `components/icons`, where every icon the app shows is named for what it means where it shows (`ContributorsIcon`), never from `@mui/icons-material` (`arkyvree/icons`)
- What shows on a condition only is `cond && <X />`, never a ternary with a `null` side; a chain of alternatives (`a ? <A /> : b ? <B /> : null`) ends in null (`arkyvree/jsx-conditionals`). A fragment is `<>`, around two children or more (`react/jsx-fragments`, `react/jsx-no-useless-fragment`)
- Group related components in folders with `index.ts` exports. Code outside a folder imports it through its `index.ts`, never a file inside it; files within the folder (its subfolders included) import each other directly, and a subfolder with its own `index.ts` is imported through that
- An `index.ts` exports what code outside its folder uses. An entry, or a whole `index.ts`, that nothing imports is dead code: delete it. Page folders have none: routes import each page file directly (most lazily, so each gets its own chunk)

## Styles

The rules are `lint/styles.mjs`'s. Every value a style takes is the theme's, written out in `client/src/theme/` alone (`appTheme.ts`: the palette, the shadows it names, how MUI's components look; `animations.ts`: durations, easings, keyframes and the animations they make; `globalStyles.ts`: the page's own; `text.ts`: `lineClampSx`); everywhere else a style names one.

- A style is `sx`: never `styled()`, no stylesheet but the fonts `main.tsx` loads, and `style` only passes on one a component is given (`{ ...props.style, … }`); a table's column is a `<Box component="col" sx={{ width }} />` (`arkyvree/sx-styles`)
- A color is a palette token (`"text.secondary"`, `"gold.main"`, `theme.palette.backdrop.top`), translucent through `alpha()`: never a hex, `rgb()` or `hsl()` color, a CSS color name or a hex alpha appended (`arkyvree/theme-colors`). The brand gold is `palette.gold`: `main` the theme's own (brighter on the dark theme), `light` and `dark` the two golds, `faint` its glow
- A shadow is an elevation (`boxShadow: 2`) or one the theme names: `theme.boxShadows.banner`, `theme.textShadows.hero`, `theme.dropShadows.authLogo` (`arkyvree/shadows`)
- A corner is in the theme's units (`borderRadius: 1`) or a circle (`"50%"`), and a corner of its own only drops to `0` beside it; spacing is in the theme's units (`p: 1.5`), never pixels; a layer above the page is the theme's (`theme.zIndex.drawer + 1`), a number orders siblings only (`0`, `1`) (`arkyvree/shape`). A border is the theme's shorthand (`border: 1`, `borderLeft: 3`), its color `borderColor`, its style `borderStyle` (`arkyvree/borders`)
- Motion is timed by `theme/animations.ts`: `ANIMATIONS.diceRoll`, `` `${fadeIn} ${DURATION.normal}ms ${EASING.decelerate}` ``, `transitionOf(["opacity"], DURATION.fast)`; keyframes and MUI's transitions (`Fade`, `Grow`…) are the theme's, and a component's timing props take its tokens (`<Collapse timeout={DURATION.normal}>`). What animates, or moves on `&:hover`, stops for a viewer who asked for less motion: its style sets `[PREFERS_REDUCED_MOTION]` too (`arkyvree/motion`)
- Text takes its style from a variant (`variant="body2"`, a responsive one in `sx`: `typography: { xs: "body1", sm: "h6" }`), sized in `rem` when it sizes itself; a font weight is a number; text aligns with `textAlign`, never `align`; an icon takes MUI's named sizes as its `fontSize` prop (`fontSize="small"`, other sizes in `sx`); lines clamp through `lineClampSx(lines)` (`arkyvree/type-scale`). A `Typography` sized as a heading or a subtitle declares its element (`component="h2"`, `"p"`), so the page's outline is a hierarchy (`arkyvree/headings`)
- A flex container is a `Stack`, its `direction` and `spacing` props (the theme makes `spacing` a gap: `useFlexGap`), never another element with a flex `display`; a grid is a `Box` (`display: "grid"`), never MUI's `Grid`; an element is a `Box` or a `Typography`, never a raw `div` or `p`; a spacer is `<Box sx={{ flexGrow: 1 }} />` (`arkyvree/flex-layout`). The gap between blocks is their `Stack`'s `spacing`, never a block's own margin (nor a field's `margin` prop): a margin only aligns (`mx: "auto"`), resets (`0`) or bleeds past its parent's padding (`mx: -2`); a heading's gutter is `gutterBottom` (`arkyvree/spacing`). Padding is a box's inner space, never a gap between siblings: inside a surface (a background, a border, a shadow), an indent, a container's space from its own edges, or space that opens and closes with its content (inside a `Collapse`: `AnimatedAlert`'s `gutter`)
- `sx` is written one way (`arkyvree/sx-conventions`): MUI's shorthand keys (`bgcolor`, `p`, `mt`); an object whose values may read the theme (`color: (theme) => …`), never a function of its own; a style on a condition and a caller's `sx` join it as an array (`sx={[{ … }, open && { … }, ...(Array.isArray(sx) ? sx : [sx])]}`); a style wins by its selector, never `!important`, but on a third party's frame (`"& iframe"`), whose inline style no selector beats. The theme's mode is branched on as `theme.palette.mode === "dark"`, in the style it picks; MUI's `useTheme` and `useMediaQuery` are `useIsMobile`'s, and the app's theme mode is `useThemeMode`'s (`contexts/`)

## API Layer

- RPC client (`client/src/services/rpc.ts`) wraps Hono's `hc` client; its fetch throws `ApiError` (`client/src/services/ApiError.ts`) for typed error handling
- `ApiError` includes `status` (HTTP code) and `errorName` (server error class name)
- The API is called through TanStack Query only: a request is made in a function a query or a mutation runs, named `…Fn` as TanStack's `queryFn` and `mutationFn` are, wherever it's handed (`useRulesetSection`'s `createFn`, an editor's `saveFn`; `arkyvree/api-calls-in-queries`). A request a click makes is a mutation, and a read it needs is `queryClient.fetchQuery`
- The RPC fetch throws `ApiError` on every non-2xx response, so never check `response.ok`. Read bodies with `parseResponse(rpc.api.x.$get(...))` (from `hono/client`), which also narrows to the success type, and a file's as a blob, `(await rpc.api.x.$get(...)).blob()` (`arkyvree/parsed-responses`). To react to a specific status (e.g. show "not found"), catch `ApiError` and test `error.status`
- Use `InferRequestType` / `InferResponseType` from `hono/client` for all API types — never recreate manually
- A query's options come from a `queryOptions` (or `infiniteQueryOptions`) factory in a `…Queries.ts` module, never written where it runs (`arkyvree/queries`): the caller does `useQuery(featQuery(id))`, or adds its own options (`{ ...featQuery(id), placeholderData: keepPreviousData }`). Queries shared across areas, or between a page and a prefetch (sidebar hover, card hover), live in `client/src/lib/queries.ts`, so the key, page size and params can't drift apart. A query keeps its previous data with `keepPreviousData`, its durations are named (`lib/durations.ts`: `FIVE_SECONDS`…), and the cache is written in a mutation's callbacks, or by the query's own module (`seedTargetPath`). An infinite query's items are `pageItems(data)`, its first page `firstPage(data)` (`lib/pageItems.ts`). Ruleset and campaign tab lists do the same in `pages/rulesets/details/sectionQueries.ts` and `pages/campaigns/details/sectionQueries.ts`, and so do the detail pages that a table row prefetches on hover: the customization page's entity in `pages/rulesets/customization/entityQueries.ts`, the simple entity pages (abilities, skills, saves…) in `pages/rulesets/details/entities/entityDetailQueries.ts`, and the class page and its tabs in `pages/rulesets/details/classes/classSectionQueries.ts`. A page renders with its factory and the hover prefetch (ruleset tab, campaign card, table row) goes through it. Every query key comes from `lib/queryKeys.ts` (`arkyvree/query-keys`: a key written as an array spreads one first)

## State Management

- **Server state**: TanStack React Query for all API data
- **Auth state**: Zustand store (`stores/authStore.ts`) with localStorage persistence: who is signed in, and the emails waiting for a code. The requests that change it are `useAuthRequests`' mutations (sign in, up and out, verify, reset; `pending` while any is in flight), and `checkSession` the private routes' probe; the query client leaves their 401s to them. Where the user goes once the session changes is the routes' to say, never a page's: a signed-in user leaves the auth pages for where they were going (`AuthLayoutRoute`: the `redirect` that sent them to sign in), a signed-out one leaves the private pages for sign in (`PrivateRoute`; `clearSession({ byUser: true })` when the user ended it, who isn't sent back). React Router applies a navigation in a transition, which the store's render runs ahead of: a page navigating as it changes the session loses to the route's redirect
- **Form state**: React Hook Form — use `form.reset()` to populate edit forms, never `key={}` remounting or `defaultValue={}`. A form is made with `useFormWith(defaultValues)` (`hooks/`), never `useForm` (`arkyvree/controlled-inputs`): its values are a whole `T`, every field the form's type requires, which TypeScript checks. A controlled field submits only what the form holds, so a field without a value would reach the server as missing. A ruleset entity's empty form is shared by its create dialog and its editor (`EMPTY_LANGUAGE`… in `pages/rulesets/components/forms/`, `EMPTY_MODIFIER` / `EMPTY_REQUIREMENT` in `components/customization`). Map a nullable text column to `""` in the form values (`description: x.description ?? ""`): an input holds `""`, so `undefined` makes the form dirty on mount. Every input is controlled, and a form's field is bound one way: through `useController`, by the shared fields (`NameField`, `DescriptionField`, `EmailField`, `PasswordField`, `FormTextField`, `SelectField`, `SwitchField`) or by `Controller` / `useController` around a custom input, never `register` and never a value `watch` reads with a `setValue` for its change (`arkyvree/controlled-inputs`). A custom input passes `field.ref` to the input element (`inputRef`), so a failed submit can focus it. An input component takes its value and its change from its owner and keeps no copy of the value; an editor with state of its own (`ConditionFields`' template mode) seeds it once as it mounts, in a dialog its form was reset for

## Hooks & Patterns

- `useDebouncedValue(value, delay?)` — shared hook for debouncing search inputs (default 300ms); a cleared value applies at once, so resetting a search never filters by the old text
- An effect synchronizes with what's outside React (a subscription, a timer, the server through `useFormSync`), and never does what an event or a render does: it never writes a form's field nor calls back its owner (an `on…` prop, a callback a ref holds; `arkyvree/effect-writes`). A change happens in the event that causes it (a picked target path seeds its operator in the pick, a picked item fills its slot as its details load), and what follows from data is derived as the component renders (a level's picks fitted to the pools its slots give, `fitPicks.ts`; a race its list no longer offers refused by the form's rules). A dialog's own state is reset by its opener (`form.reset`, the publish dialog's kind) or lives in a body the dialog unmounts as it closes (the extension picker's selection)
- `useOnChange(value, onChange)` (within `hooks/`: `useSearchText` uses it, and the index exports it once a component needs it) — follows a value from outside React's state into the state a component keeps, in the render that sees it change, never an effect that sets state (`react/set-state-in-effect`): `useSearchText`'s text takes the URL's at a navigation. Derive what can be derived during render instead
- `useRulesetSection` — generic CRUD hook for ruleset detail sections (queries, mutations, dialogs, forms); spread its `createDialogProps` into the section's `CreateDialog`
- `useRulesetPermissions(ruleset)` — the single source of ruleset edit / manage / publish rights on the client
- `useFormSync(form, values, { key, updatedAt })` — keeps an inline edit form in step with server data without wiping unsaved edits on refetch; use it instead of an effect that calls `form.reset()` whenever the query data changes. `key` is the record from the URL (include the ruleset id for ruleset entities: inherited ones keep their id in every fork), so opening another record resets the form. A page that follows a copy-on-write to the copy passes the source's key as `adoptKey`: a form still holding the source takes the new key over and keeps its unsaved edits. Submit through `sync.handleSubmit`, send `sync.updatedAt()` as the save's stale-edit token, and on success call `sync.saved(values, response.updatedAt)` instead of `form.reset()`
- `useListParams(sortFields, defaultSort)` — a list page's search and sort from the URL, plus the `searchBarProps` that change them: the search is the hook's state (`SearchBar` is controlled; the router applies a URL change in a transition, which can't feed a text input), written to the URL as it's typed and taking the URL's at Back or a link, and `search` is it debounced, for the query. `useSearchText(key)` does the same for a section's search. `useSearchParam` for any other filter; `oneOf()` (`lib/oneOf.ts`) validates enum params. Sort options come from `NAME_SORTS` / `CREATED_SORTS` / `UPDATED_SORTS`
- `useNotificationActions` — accept / reject invites, download exports and open targets for any notification surface
- `useRulesetAbilities(rulesetId)` / `useRulesetSaves(rulesetId)` / `useRulesetLanguages(rulesetId)` — the ability / save / language lists for pickers and columns (the first 100 of each, the most one request returns; rulesets have far fewer); don't query them ad hoc. `useRulesetFeats(rulesetId, search)` is the feat picker's list: a ruleset has hundreds, so it searches the server and pages in as the listbox scrolls
- `useOpenEntity(rulesetId)` — opens a ruleset entity's page with the current list as its Back target; `entityPageState(location.state)` reads that target back
- `useValidationIssues()` — a save the server can refuse with rules warnings: shows them in the form (with a force save), toasts anything else
- `useToggleSet()` — expanded rows / open groups, toggled one key at a time
- `useDialogState<T>()` — a dialog opened for a record, or for nothing (`true`): `target`, `open`, `openWith`, `close`, `onExited`
- `useAnchorMenu()` — a menu that opens from what was clicked: `anchorEl`, `open`, `openMenu` (the button's click), `closeMenu`, and `closeMenuAnd(then)` for an item's click (`arkyvree/anchor-menus`)
- Infinite listboxes: `useListboxQuery(options)` returns the loaded `items` and the listbox's `onScroll`; give the listbox `ScrollSafeListbox`. Several queries behind one listbox share a `createListboxScrollHandler([...])` (`lib/listboxScroll.ts`); flatten any other infinite query with `pageItems(data)` (`lib/pageItems.ts`)
- A query that can't run yet passes `skipToken` as its `queryFn`, in its factory (not `enabled: !!id`, which `arkyvree/queries` refuses); `enabled` is for plain on/off gates
- Untyped JSON (activity and notification payloads, stored state) is read through `isRecord` (`shared/isRecord.ts`) guards, not casts
- What the browser keeps is a store's (`client/src/stores/`: zustand's `persist`, or a module of its own, `themeModeStorage.ts`), never `localStorage` or `sessionStorage` elsewhere (`arkyvree/browser-storage`). The URL's search params are read through the shared hooks (`useSearchParam`, `useListParams`, `useSearchText`, `useUpdateSearchParams`), never `useSearchParams` elsewhere (`arkyvree/navigation`). A date is shown through `lib/formatDate.ts` (`formatDate`, `formatDateTime`, `formatRelativeTime`), in the viewer's language (`arkyvree/date-formats`)
- Mutations use `.mutate()` with `onSuccess`/`onError` callbacks, not `.mutateAsync()` (`arkyvree/client-apis`)

## Shared UI building blocks

a character's is `CharacterHeader`, `components/characters`, its name renamed in place), `ListToolbar` (the bar above a list, a page's or a tab's: what narrows or picks at its start, its actions at its end; `SearchBar` is one, and a tab is never titled: its tab names it), `PageActionButton` (the create action in a list page header and empty state, a large `AddButton`), `AddButton` (any button that adds something: its label and the add icon; `arkyvree/add-buttons`), `LinkButton` (an action written as a link, "Resend code"; `arkyvree/link-buttons`), `ChoiceChip` (a chip that is one of several to choose, filled while picked; `arkyvree/choice-chips`), `DialogFooter` (a dialog's footer: its way out, then its action, pending with a spinner, or its own steps; `arkyvree/dialog-footers`), `NextPageSpinner` (the foot of a list that loads its next page as it scrolls; `arkyvree/next-page-spinners`), `LoadMoreButton` (paginated lists), `BlankState` (a page's or a tab's empty list: its icon, its title and its line, all required; it applies the icon's standard size and tint), `BlankNote` (an empty list in a panel, a dialog, a menu or the level wizard, said in one line; `arkyvree/blank-notes`), `CardTitle` (a card's or a panel's title: a sheet section's, a profile card's, an entity page's; `arkyvree/card-titles`), `SubsectionTitle` (a heading under a card's title, in a panel, a dialog or a wizard step: a subtitle at 600, 8px above its content, the column it leads taking `spacing={1}`) and `EntryTitle` (an entry's name in a panel's list: a feat on the sheet, a bonded creature), the only headings under a card's (`arkyvree/section-headings`), `EmptyValue` (a value that isn't there: "—", muted; `arkyvree/empty-values`), `TableFrame` (the frame of a table on a page or in a dialog: outlined, under the theme's header, which no cell restyles; a table in a panel stands bare; `arkyvree/table-frames`), `PageLoader` (a page's first load, a route's `Suspense` fallback too; `arkyvree/page-loaders`), `SectionContent` (a tab's centered column), `LoadError` (a list, a section or a step that failed to load: `<LoadError what="Feats" error={error} />`, in `loadFailureMessage`'s words, with an optional Retry; `arkyvree/load-errors`. What reads a query shows its failure, where its data shows, while there's none to keep: a section's table takes its query's `error` and names `what` it lists, a picker says it as its options would (`noOptionsText={emptyOptionsText("Items", error)}` from `lib/errorMessage.ts`, `RulesetPicker`'s `loadError`), a select or a field under it (`SelectField`'s `loadError`, `TargetPathInput`); the app's hooks that hand on a query (`useListboxQuery`, `useRulesetSaves`…) hand on its `error` too, and an image (`useAttachment`) shows its placeholder either way; `arkyvree/query-errors`), `PageError` (a page that failed to load, with its way back; `loadFailureMessage(what, error)` from `lib/errorMessage.ts` gives its text, always (`arkyvree/page-errors`). Show it only when there's no data (`if (!data)`), so a failed background refetch doesn't replace a loaded page. Pages showing a record others control (campaign, campaign character, shared sheet) also show it on `accessLost(error)`: a 404 / 403 means it was deleted or access was revoked), `ActionMenuItem` (a menu's action: its icon, its label, its intent's color, a page of the app with `to` or an outside page with `href`, its click then only closing the menu; a `MenuItem` is one of several to choose, marked `selected`, and a menu holds its items alone: a panel that opens from a button, the notification bell's, is a `Popover`; `arkyvree/menus`), `NameField` / `DescriptionField` / `EmailField` / `PasswordField` and `FormTextField` for any other text field (bound to a form's field: `control`, `name`, `rules`, its rules named, never written in place (`NAME_RULES`, `requiredRules("Level is required")` from `lib/validation.ts`; `arkyvree/form-fields`); a number field (`FormTextField number`) validated by the form takes `wholeNumberRules(min, required?, max?)` from there, its native `min` / `max` kept only for its stepper, and an input outside the form's own fields (a list's: a level's saves) says `wholeNumberError(value, min, max)` while its field's `validate` checks the list), `SelectField` (a form's select, numbers too (a hit die), a first choice for none with `emptyLabel`, what follows from a pick in its `onChange`; `arkyvree/select-fields`), `SwitchField` (a form's switch), `RulesetPicker` + `BaseRulesetAlert` (a create dialog's ruleset), `ValidationIssueList`, `ValidationIssuesAlert` (a save's rules warnings at the form's top, with Proceed Anyway; `useValidationIssues`) (no other alert carries actions: a confirmation is a `ConfirmDialog`, over a dialog too; `arkyvree/confirm-dialogs`). A select outside a form is a `TextField select`: `FormControl` + `InputLabel` + `Select` leaves the combobox without an accessible name. Ruleset tables use `DescriptionCell` and `AptitudeChipsCell`, and spell lists `SpellLevelFilter` (`pages/rulesets/components`); the level-up wizard's options show what they are, or what they ask that the character lacks, through `OptionTooltip` (`arkyvree/option-tooltips`). A form is `noValidate`: its rules check its fields and say why, never the browser's bubble, so a bound field that asks the browser to check it (`required`, `type="email"`) has `rules` (`OPTIONAL_EMAIL_RULES` for an email that may be left empty) and one with native bounds checks them with `wholeNumberRules` (`arkyvree/form-validation`). Formatting helpers live in `lib/formatNumeric.ts` (`formatSigned`, `formatCount`, `formatCost`, `formatWeight`) and `lib/errorMessage.ts`; an empty value is an `EmptyValue`. A page's content sits 32px under its header (`PageHeader`, `DetailPageHeader`, `CharacterHeader`): the column holding it takes `spacing={4}` (`arkyvree/page-gaps`). What the app says is said one way: a label (a button's, a menu item's, a toggle's, a tab's, a field's, a dialog's title, an icon button's tooltip, any `aria-label`) is in Title Case, "Mark All as Read" (`arkyvree/label-case`); an ellipsis is "…" and a dash between words "—", and a text cut short is `truncate(text, length)` (`lib/truncate.ts`; `arkyvree/typography-marks`). Reuse them rather than restyling a copy.

## Toast/Snackbar

- Queue-based `SnackbarProvider` in `contexts/SnackbarProvider.tsx` — notifications process sequentially
- Use `useSnackbar()` hook: `snackbar.success()`, `snackbar.error()`, etc.
- Never use `console.error` for user-facing errors — always use snackbar. An error's toast names what failed when the error has no message of its own (`snackbar.error(error, "Failed to archive campaign")`); an error shows through `errorMessage(error, fallback)`, never its raw `message`, and is told apart by its `errorName` (`EmailNotVerifiedError`), never its words (`arkyvree/error-reads`)
- A toast is a phrase: "Ruleset archived", "This export expired: generate a new one", no final period or "!", no "successfully" nor "Please" (`arkyvree/toast-wording`)

## Loading Indicators

- Always use `<DiceSpinner>` (`components/common/DiceSpinner.tsx`) — never MUI `CircularProgress` (`arkyvree/client-apis`)
- For Buttons, use the wrapper API so the button doesn't shrink when loading flips: `<DiceSpinner size="small" loading={isPending}>Save</DiceSpinner>` as the Button child. Pair with `disabled={isPending}`. Keep any static `startIcon` outside the wrapper. Every button that starts a request shows it running this way, an icon button's icon too (`arkyvree/pending-buttons`).
- A page's first load, a route's `Suspense` fallback too, is a `PageLoader` (the character sheet draws a skeleton of itself instead). A section's or a dialog's loader is a standalone `<DiceSpinner />` (default medium); it centers itself, so give it a section's spacing through `sx` (`<DiceSpinner sx={{ py: 4 }} />`) and nothing else, never a box around it, a height or the large size (`arkyvree/page-loaders`)

## Dialog Conventions

- Pick the wrapper by purpose — there is no lint rule to choose between them, only a convention:
  - **`CreateDialog` / `EditDialog`** (from `StandardDialogs.tsx`): standard create / edit shapes. Default for create or update flows.
  - **`FormDialog`**: any other dialog that contains a React Hook Form. Binds the form, registers with the global dirty-tracker, blocks backdrop / Escape close while dirty.
  - **`ConfirmDialog` / `DeleteDialog`** (from `StandardDialogs.tsx`): yes/no confirmations, over a page or over the dialog that asks (the level wizard's discard, the share link's revoke). Set `confirmColor` by intent (`warning` for Archive / Leave, `success` for Publish, `error` for destructive) and `confirmLabel` to the action ("Archive Character", not "Confirm"). `DeleteDialog` is the `error` preset. A confirmation asks "Are you sure you want to …?", then says what follows; a deletion ends "This action cannot be undone." (`arkyvree/confirm-wording`).
  - **`Modal`**: info dialogs and manager dialogs that don't bind a form. **Never wrap a `<form>` in `Modal`** — Modal skips the dirty-close guard, so backdrop click / Escape discards typed input (`arkyvree/dialog-conventions`).
- Dialog title and action-bar styling come from the theme — use a plain `<DialogTitle>` without extra typography or padding, and end the dialog with a `DialogFooter` (`onCancel`, its `cancelLabel` "Close" when there's nothing to confirm, an `action` with its label, color, icon and `onClick` (a submit without), `pending` while it saves, or its own steps as children), never `DialogActions` by hand (`arkyvree/dialog-footers`).
- Manager dialogs with both a list and an invite form: keep the outer `Modal` for the manager and put the form in a nested `FormDialog` opened from an Invite button.
- Edit dialogs receive a `form` prop (from React Hook Form) — parent calls `form.reset({ ...data })` before opening. A create dialog's form is reset as it opens too (`useRulesetSection`'s `handleCreate`), never after a save, so a cancelled one reopens empty
- A dialog stays mounted, its `open` showing it, so it fades out as it closes. A dialog about a record (a row, a level) opens through `useDialogState` (`dialog.openWith(row)`, `open={dialog.open}`, `dialog.target`), which keeps the record while it fades; one that keeps state of its own (the level wizards) mounts with that record (`{dialog.target && …}`) and lets it go once faded (`onExited`), so it opens clean (`arkyvree/dialog-mounts`)
- Dialog components should not receive the selected entity as a prop — form state is the source of truth
- Form-bearing dialogs must block backdrop click and Escape when `form.formState.isDirty` so users don't lose work. `CreateDialog`/`EditDialog` from `components/common/StandardDialogs.tsx` handle this — prefer them. For custom dialogs, replicate: `onClose={(_, reason) => { if ((reason === "backdropClick" || reason === "escapeKeyDown") && form.formState.isDirty) return; onClose(); }}`

## Other shared pieces

What the sections above don't name, so no one writes a second one:

- **Components** (`components/common`):
  - `NoMatchesState`: a page's or a tab's search that found nothing, told apart from an empty list (`BlankState`).
  - `PageTransition`: a page's fade in.
  - `StyledCard`: the card under `ListCard`. Use `ListCard` for a grid.
  - `SectionTab`: the type of a `SectionTabs` tab.
  - `FilterOption` and `SortOption`: the types of `SearchBar`'s menus.
  - `FaqHelpIcon` and `faqTooltip`: a help icon with an FAQ answer in its tooltip.
  - `HelpLabel`: a label with its help icon (a tab's, a field's).
  - `AttachmentField`: an uploaded image, a portrait or an avatar, with its upload and removal.
  - `Crossfade`: one content crossfading into another.
  - `GoldDivider`: the dashboard's gold rule, with an optional label.
  - `ErrorBoundary`: the app's render-error page, around the routes in `App.tsx`.
- **Hooks** (`hooks/`):
  - `usePageTitle`: the browser tab's title.
  - `useStaggerAnimation(listKey)`: the offset that animates only a list's newly loaded page.
  - `useDirtyForm(isDirty)`: an inline form's unsaved edits guard the page's close and refresh. `FormDialog` already calls it.
  - `useLatest(value)`: a ref to the latest committed value, for an effect or a handler.
  - `usePdfExport(requestPdf)`: queues a PDF export, whose ready notice comes later.
  - `useAttachment` and `useAttachments`: an image's URL, or several, cached per id.
  - `useDirectUpload(slot)` and `useDetachAttachment(slot)`: upload an image to its slot, and remove it.
  - `useGoogleSignIn(onToken)`: Google's sign-in button.
  - `useStartDemo` and `useDemoTimeRemaining`: start a demo account, and the time its session has left.
  - `useOglLicense`: the Open Game License's text.
  - `useOpenActivityTarget` and `isNavigableTarget`: open an activity's or a notification's target page, and whether it has one.
